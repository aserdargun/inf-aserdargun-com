# Architecture

The statically exported Next.js client is served by Azure Static Web Apps. Managed Node 22 Functions own all Drive and learning mutations. The browser has no Google credential and never accesses private Drive data directly.

Public `/view*` requests use explicit allowlisted projections. Owner APIs independently verify GitHub `aserdargun`; SWA route roles are a second boundary. Private learning state is append-only schema-versioned JSON events in a restricted Drive sibling, folded deterministically by occurrence time and event ID. Public originals and thumbnails remain under the approved public Drive root.

The approved public root contains `Inbox`, `Library`, `Archive`, `Duplicates`, and `Thumbnails` and retains exact owner plus non-discoverable `anyone:reader` access. The owner may upload images manually to `Inbox`; **Sync Drive** validates and indexes them. Public View Mode can then display the image through the public-safe projection, but it never exposes private learning metadata. The sibling `INF-PRIVATE-DATA` root contains lowercase `events`, `reviews`, `quarantine`, `exports`, and an owner-only `integration-test` root. Private and test roots must read back as owner-only; missing permission metadata is a hard failure.

Desktop OAuth uses the full Drive scope because INF must read the pre-existing public root and files manually uploaded outside the app. The bounded callback listens only on `127.0.0.1`, verifies cryptographic state and PKCE S256, confirms `aserdargun@gmail.com` through Drive `about`, and stores credentials plus derived audit IDs only in ignored mode-0600 `.env.local`. Azure receives only the API-required runtime subset; audit and integration IDs remain local.

For local release validation only, `INF_LOCAL_STORAGE_MODE=true` selects `LocalDriveAdapter` iff bypass is exact, `WEBSITE_SITE_NAME` is absent, the request is loopback, and a per-run server-side capability matches. Any failed gate falls back to the normal Google configuration requirement. A checkout-owned Node adapter binds `127.0.0.1:7071` and invokes the compiled Azure Function handlers with the same Request/response contract; deployment continues to use Azure's managed Functions runtime. The SWA emulator on 4280 talks to a loopback API proxy on 7072; that proxy injects the secret capability before forwarding to 7071. Browser assets, local storage, and control output never contain the capability.

Local objects use one non-empty `<fileId>.inf-bundle/` pathname containing immutable `data` and `metadata.json` files. Parent and trash state are derived from the bundle's directory, so create publishes a complete staged bundle with one rename and move/trash claims and publishes that unchanged whole bundle with one rename at each boundary. Every injectable fault runs before the final destination rename; rollback attempts one atomic bundle restore. A foreign non-empty source or destination bundle cannot be replaced, and a contested original remains whole under `.operations/<uuid>` as explicit quarantine. There is no fallible shared-path cleanup after commit.

The earlier split `.blob` + `.inf-meta.json` local format is deliberately not migrated: local simulation state is ignored, checkout-private, and disposable rather than production data. Detection fails with an explicit reset instruction. After Stop, `node scripts/clean-output.mjs .codex/run/storage` resets it before the next Run.

`pnpm preview:codex` changes only the web child to the immutable `out/` server. Compiled Functions, private capability proxy, SWA emulator, auth gates, local storage, and bounded Stop behavior are the same as normal Run, making it the deterministic production-artifact visual and release-evidence path.
